# WarpDrive Migration Design

**Date:** 2026-05-04
**Status:** approved
**Tracking doc:** docs/work/backlog/2026-05-03-emberdata-6-warpdrive-migration.md

## Goal

Migrate rfc-embers from EmberData 5.8.x to EmberData 6 / WarpDrive, clearing two
deprecations that become hard errors in EmberData 6:

| Deprecation ID | Scope |
|---|---|
| `ember-data:deprecate-legacy-imports` | `@ember-data/adapter`, `@ember-data/serializer`, `@ember-data/store`, `@ember-data/json-api` subpackage imports |
| `warp-drive:deprecate-legacy-request-methods` | `store.findRecord`, `store.query` call sites in routes |

## Approach: Minimal Bridge (Option A)

Keep `RfcAdapter` and `RfcSerializer` unchanged. Bridge the new WarpDrive request
API to the existing adapter/serializer pipeline using `LegacyNetworkHandler`, which
is already auto-configured by the `ember-data` umbrella package.

This is intentionally a minimal-change migration: the hexagonal `RfcGateway` boundary
is untouched, the adapter/serializer behavioral layer is untouched, and no new
abstractions are introduced.

## Architecture

The `ember-data` umbrella package (which this app already uses) automatically
configures a `RequestManager` with `LegacyNetworkHandler` and a JSON:API cache into
the default store. No custom store service class is needed.

`LegacyNetworkHandler` reads the `op` field embedded by the WarpDrive builder and
dispatches to the corresponding adapter method:

- `op: 'findRecord'` → `RfcAdapter.findRecord()` → `gateway.fetchOne(id)`
- `op: 'query'` → `RfcAdapter.query()` → `gateway.fetchAll()`

The URL generated by the builder is irrelevant: `RfcAdapter` overrides both methods
completely and never delegates to the HTTP layer.

```
Before:
  Route → store.findRecord / store.query
            └── Adapter → Gateway

After:
  Route → store.request(builder)
            └── RequestManager (auto-configured by ember-data)
                  └── LegacyNetworkHandler → Adapter → Gateway
```

`app/services/store.ts` stays as a thin re-export — no changes.

## File-by-file Changes

### Import surface only (no behavior change)

| File | Change |
|---|---|
| `app/adapters/rfc.ts` | `@ember-data/adapter/json-api` → `ember-data/adapter/json-api` |
| `app/serializers/rfc.ts` | `@ember-data/serializer/json-api` → `ember-data/serializer/json-api` |
| `app/serializers/application.ts` | same |

### Import + logic

**`app/routes/rfcs.ts`**

```ts
// before
import type Store from '@ember-data/store';
return this.store.query('rfc', {});

// after
import { query } from '@ember-data/json-api/request';
import type Store from 'ember-data/store';
const { content } = await this.store.request(query('rfc', {}));
return content.data;
```

**`app/routes/rfc.ts`**

```ts
// before
import type Store from '@ember-data/store';
return this.store.findRecord('rfc', params.rfc_id, { reload: true });

// after
import { findRecord } from '@ember-data/json-api/request';
import type Store from 'ember-data/store';
const { content } = await this.store.request(findRecord('rfc', params.rfc_id));
return content.data;
// Note: reload: true drops — every store.request() call is a fresh fetch
```

### Unchanged

| File | Reason |
|---|---|
| `app/services/store.ts` | Auto-configured by umbrella package |
| `app/models/rfc.ts`, `app/models/author.ts` | `@ember-data/model` is not in the `ember-data:deprecate-legacy-imports` deprecation scope per the tracking doc. Verify during implementation whether warnings fire; fix if they do. |
| `app/gateways/rfc-gateway.ts` | No EmberData imports |
| `app/sources/github-rfc-source.ts` | No EmberData imports |
| All templates and components | No EmberData imports |

### `package.json`

- Bump `ember-data` from `~5.8.2` → `~6.x` in `devDependencies`
- Remove from `devDependencies`: `@types/ember-data__adapter`, `@types/ember-data__model`,
  `@types/ember-data__serializer`, `@types/ember-data__store` (EmberData 6 ships its own types)
- Verify whether `@ember-data/adapter`, `@ember-data/json-api`, `@ember-data/serializer` in
  `dependencies` are still needed as explicit deps in v6 or are subsumed by the umbrella package

## Testing

### Principle

Tests must target behavioral contracts, not implementation details of the adapter/serializer
layer. All new tests must pass both before and after the migration without modification.
No existing tests may be disabled or modified unless the class/method they test becomes dead code.

### New tests to add before migration

Add these tests **before** touching any production code so they serve as a regression net.

#### `tests/unit/routes/rfcs-test.ts` (new file)

- **`model() returns an array of RFC records from the gateway`**
  Register a mock gateway that implements `RfcGateway` and returns a minimal JSON:API
  collection document (one RFC resource + one author included). Call `route.model()`.
  Assert: result is array-like, `result[0].title` / `result[0].status` match the fixture.

- **`model() surfaces all records returned by the gateway`**
  Return two RFCs from the mock gateway. Assert `result.length === 2`.

#### `tests/unit/routes/rfc-test.ts` (new file)

- **`model() returns a single RFC by id`**
  Register a mock gateway returning a singular JSON:API document for id `'1'`. Call
  `route.model({ rfc_id: '1' })`. Assert record attributes match the fixture.

- **`model() throws for non-numeric ids`**
  No gateway needed. Assert `route.model({ rfc_id: 'abc' })` rejects with an error
  matching `"Invalid RFC id"`.

#### Additions to `tests/unit/adapters/rfc-test.js` (existing file)

- **`query() delegates to gateway.fetchAll()`**
  Register a mock gateway. Look up the adapter. Call `adapter.query(undefined, undefined, {})`.
  Assert the mock gateway's `fetchAll` was called and the returned value is the gateway's document.

- **`findRecord() delegates to gateway.fetchOne() with the correct id`**
  Register a mock gateway. Call `adapter.findRecord(undefined, undefined, '42')`.
  Assert `fetchOne` was called with `'42'` and the returned value is the gateway's document.

### Existing tests (unchanged)

| File | Status |
|---|---|
| `tests/unit/adapters/rfc-test.js` — `it exists` | Passes: adapter class still registered |
| `tests/unit/serializers/rfc-test.ts` — dasherization tests | Passes: serializer class unchanged |

## Order of Operations

1. Add behavioral tests (routes + adapter additions) — verify all pass on current code
2. Fix `@ember-data/*` import paths in adapters and serializers — verify `ember-data:deprecate-legacy-imports` clears
3. Convert route call sites to `store.request()` builders — verify `warp-drive:deprecate-legacy-request-methods` clears
4. Bump `ember-data` to `~6.x`, remove `@types/ember-data__*` shims — verify `lint:types` passes
5. Verify model imports (`@ember-data/model`) — fix if they fire deprecations in v6
6. Remove `@ember-data/{adapter,json-api,serializer}` from `dependencies` if no longer needed
7. Full `npm run test:ember` — zero deprecation warnings for both IDs
8. Manual smoke test: RFC list and detail routes load real data from GitHub
